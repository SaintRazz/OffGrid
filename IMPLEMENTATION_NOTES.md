# Transfer and simulation update

Changed systems: `simulation.py`, `resources.json`, `static/script.js`; regression coverage is in `tests/test_transfer_update.py`.

Resource metadata retains native units and adds `mass_per_native_unit_lb`. Water is 8.34 lb/gal, eggs 0.125 lb/egg, hens 5 lb/bird. Loose bulk uses `bulk_density_lb_per_gal`; liquids use `volume_per_native_unit_gal`. A bucket is a discrete, orderable 2 lb item with 5 gal capacity. Water, compost, active compost, scat, and insect forage require bucket space. Feed and browns retain their existing direct carrying behavior. Eggs and birds consume mass but no bucket space.

The server accepts `amount: "all"` on physical-transfer routes. Queue admission uses `projected_player_inventory(queue_index=None)`: start with physically carried inventory (including legacy prepaid cargo), then replay pickups/collections and outgoing deliveries in execution order. Each pickup respects the 50 lb mass limit and shared bucket volume at that step. Earlier deposits can free capacity for later pickups; later deposits cannot justify earlier overload. Bucket pickups can supply later bulk collections once their task completes. Source and destination reservations remain authoritative on the backend.

New facility deliveries and House Storage drop-offs reserve projected stock using `reserved_cargo.source = "projected_player"`; they consume actual carried stock at completion. Legacy `source = "player"` deliveries and garden work retain immediate reservation/refund semantics. Projection supports both formats without rewriting saves. `transfer_limits.projected_inventory` exposes availability at the queue end; facility `deposit` limits also apply destination reservations. `collect_stock` exposes actual unreserved local output separately from the `collect` limit constrained by weight and containers.

Cancellation and each execution step reconcile the queue in order. A dependent transfer shrinks to the valid remaining quantity, or is cancelled when zero. Reserved source stock is refunded where applicable. Reconciliation never increases a task, duplicates material, or refunds a future delivery as though it already existed. Adjustments appear in task descriptions, `task_adjusted` events, and recent task queue notes. Execution rechecks destination capacity and consumes only actual available cargo.

BSFL pre-compost uses `active_compost` from `residue_mass` throughout summary, collection UI, server validation, reservation, and completion. Manage Contents now distinguishes accumulated stock from the legal pickup amount and explains carry/bucket restrictions.

Map facilities use full logical-footprint wrappers around their sprites and coordinate-based facility lookup. Dimensions, placement, and pan logic are unchanged. Hover titles append human-readable accrued labor only above 20 minutes, using `accrued_labor_requirement` for every facility type.

Save compatibility: additive resource metadata and response fields require no destructive schema migration. Existing alias, single-task, coordinate, compost-pool, forage, and egg migrations remain. Household task targets are refreshed at runtime, including tasks loaded from old saves, so they approach adjacent tiles. Existing inventory is preserved, including legacy overweight inventory; new pickups stay blocked until enough mass has been deposited. Existing saves are not rewritten by implementation or tests.

Compatibility audit: `current_task` is still consumed by the frontend; x/y, type/facility_id and public response aliases remain. Rotation parameters remain in placement/instance normalization; the current API supplies false. `/api/subtick` and `/api/player/inventory/transfer` have no current frontend callers, but external callers cannot be ruled out, so both routes and their wrappers remain. Old resource aliases still participate in save loading and are retained. Migration work remains in normalization; transfer rules live separately in runtime helpers.

Validation: 30 targeted regressions pass; Python syntax, all six root JSON files, and JavaScript syntax pass. JavaScript was parsed with the VS Code bundled Node runtime because standalone Node is absent. The old `tests/test_app.py` cannot collect: it imports `calculate_system_preview`, absent from the current app, and its fixtures target a superseded no-argument Simulation API. This pre-existing suite was preserved for a separate migration.


Targeted push validation: 85 Python regressions pass across `test_garden.py`, `test_transfer_update.py`, and `test_queue_projection.py`. `test_map_ui.js`, `test_garden_ui.js`, and `test_runtime_ui.js` pass with the VS Code bundled Node runtime. Map checks cover footprint corners, all occupied tiles, grass selection, placement, drag-click suppression, and labor formatting/thresholds. Syntax checks cover Python, JavaScript, and root JSON. The pre-existing `test_app.py` collection incompatibility described above remains separate. No existing save was edited.
